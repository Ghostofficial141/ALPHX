### Unit Rules (CRITICAL — violating these causes automatic check failure):
These rules are strictly enforced by the BRAIN platform. Violating any of them will result in a UNIT_HANDLING check failure and the alpha will NOT be submittable.

1. **Never use GROUP fields directly in arithmetic.** Fields marked (GROUP) — such as `sector`, `industry`, `subindustry`, `market`, `country`, `exchange` — are categorical. They can ONLY be used as the grouping argument of group operators (e.g., `group_rank(x, sector)`, `group_mean(x, industry)`). Do NOT add, subtract, multiply, divide, or apply numeric operators to them.

2. **Never mix Matrix and Vector types without an explicit operator.** Multiplying a MATRIX field by a VECTOR field is not allowed unless the operator explicitly accepts mixed types.

3. **Always normalize before combining.** When combining two MATRIX fields arithmetically, apply `rank()`, `ts_rank()`, or `scale()` to each before the operation to avoid unit mismatch warnings.

4. **Allowed arithmetic operand types are MATRIX and VECTOR only.** GROUP fields are never valid arithmetic operands. SCALAR constants (e.g., 0, 1, 5) are fine.

5. **ts_* operators (ts_mean, ts_std_dev, ts_sum, etc.) require a MATRIX input** — never pass a GROUP field to them.

6. If the previous iteration reported a UNIT_HANDLING error, read the message carefully and fix the exact operator/field combination that caused it. Do not introduce the same pattern again.
